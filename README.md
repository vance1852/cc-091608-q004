# 跌倒救援编排

独居长者腕表的跌倒候选信号，经过**询问佩戴者 → 联系人确认 → 急救升级 → 结束**的状态机编排。
设备离线与消息提供商重试都会产生重复消息，因此每个外部事件带稳定 `eventId`：一条事件对应
唯一一条救援链（`rescueId = rescue-<eventId>`），重复包只计数、绝不另起时间线。

`src/contracts.ts` 定义跌倒信号、联系人、时间线、持久化定时器与位置授权等结构；
`fixtures/fall-scenarios.json` 汇集**误触取消、无人响应、离线补传**三种脱敏经过。

## 针对家庭诉求的保证

- **减少无谓惊扰，但救援不被阻断**
  - 设备报告离腕（`worn:false`，如腕表落在沙发上）只进入佩戴者询问，不呼叫联系人；
  - 普通取消仅在 `cancelWindowSeconds` 时限内、且告警无高风险特征时有效；
    强冲击 / 姿态改变且长静止 / 长时离线补传任一成立即为高风险，普通取消无法关闭；
  - 联系人静默时段只跳过本人并立即顺延；联系人确认超时继续下一位；链耗尽必升级急救；
  - 急救呼叫失败会无限间隔重呼直到受理，提供商故障无法阻断救援。
- **回执、超时、重试汇入同一救援链**：呼叫回执（delivered/failed）、确认窗口超时、
  提供商重试（含网络异常）都挂在同一 `rescueId` 下，时间线只此一条。
- **位置最小授权**：位置仅授予"当前响应人"且为短时窗口（默认 10 分钟）；
  响应人切换或告警结束即撤销；每次读取（允许、过期、撤销、非响应人、未知令牌）全部留痕。
- **中途重启可续跑**：每次状态跃迁与"下一次动作"（询问超时 / 联系人超时 / 提供商重试）
  都随状态原子落盘（临时文件 + rename）。重启时按持久化的 pending 定时器重新注册，
  已过触发时刻的动作立即补跑。
- **查询稳定**：晚到的旧事件补传后，家属查询仍得到唯一、按发生时刻排序的时间线
  （`entryId` 为 `rescueId-序号`，跨时区写法按同一瞬间比较），以及完整的升级原因与当前响应人。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `src/contracts.ts` | 全部对外数据结构与原因码 |
| `src/policy.ts` | 家属策略（联系人顺序、静默时段、时限、阈值）、风险分级、取消判定 |
| `src/orchestrator.ts` | 事件去重、状态机、串行化跃迁、持久化定时器与重启恢复 |
| `src/provider.ts` | 通知提供商端口（回执/失败），含确定性脚本实现 |
| `src/location.ts` | 位置短时授权、撤销与每次读取留痕 |
| `src/store.ts` | 持久化端口：内存实现 + JSON 文件原子写实现 |
| `src/timers.ts` | 定时器宿主：真实时钟与可确定性回放的虚拟时钟 |
| `src/replay.ts` | 将 fixtures 三段经过（含多次"重启"）回放为救援链 |
| `src/demo.ts` | 端到端演示（文件持久化，打印时间线/升级原因/位置留痕） |
| `src/scenarios.test.ts` | 15 个 node:test 用例 |

## 运行

面向 Node.js 22 与 TypeScript（直接运行 `.ts`，无需构建步骤）：

```bash
npm install
npm test     # 类型检查 + 15 个用例
npm run check
npm run demo # 回放 fixtures，打印三个样例的完整时间线
```

## fixtures 到行为的映射

- **误触取消（fall-1）**：`worn:false` → 离腕询问；10 秒内佩戴者取消即关闭；
  告警结束后链路层重传到达，仅 `duplicateCount +1`。
- **无人响应（fall-2）**：`worn:true, stillSeconds:90` → 高风险；女儿首次语音呼叫被
  提供商丢弃，20 秒后重试送达并开放位置；三位联系人确认窗口全部超时 → 升级急救并受理。
- **离线补传（fall-3）**：09:10 采集、12:40 才收到，210 分钟延迟本身构成高风险特征；
  佩戴者 29 秒时的普通取消被拒并记录原因，询问超时后女儿确认接手。
