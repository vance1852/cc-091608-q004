# 跌倒救援编排

记录腕表跌倒候选、家庭联系人策略和救援处置时间线。设备离线与消息提供商重试都可能产生重复消息，因此每个外部事件带有稳定标识。

`src/contracts.ts` 定义跌倒信号、联系人与时间线动作；`fixtures/fall-scenarios.json` 汇集误触取消、无人响应和离线补传三种脱敏场景。

代码面向 Node.js 22 与 TypeScript，安装依赖后通过 `npm test` 进行类型检查并回放三段场景（全部带断言）。

## 模块

| 文件 | 职责 |
| --- | --- |
| `src/contracts.ts` | 对外数据契约（信号、联系人规则、时间线条目）。 |
| `src/policy.ts` | 质量评估与策略常量：高风险特征、离线/陈旧判定、取消时限、跨午夜静默时段。 |
| `src/state.ts` | 持久化记录模型；`JsonRescueStore`（原子写）与 `MemoryRescueStore`。 |
| `src/provider.ts` | 通知提供商端口；呼叫回执与重试均经此进入同一条链。 |
| `src/orchestrator.ts` | 核心服务：去重接入、状态机、联系人/急救升级、位置授权、重启恢复。 |
| `src/query.ts` | 家属查询视图：唯一且顺序稳定的时间线、升级原因、当前响应人。 |
| `src/family-policy.ts` | 联系人顺序、静默时段、渠道与家属时区。 |
| `src/clock.ts` | 时钟抽象，支持确定性回放。 |
| `src/demo.ts` | 三段 fixture 的端到端回放与不变量断言。 |

## 关键不变量

- **按事件标识去重**：同一 `eventId` 的重复送达（提供商重试、离线补传重复）只累加 `deliveryCount`，绝不产生第二条救援链或重复时间线。
- **取消受策略约束**：普通取消只有在策略时限（默认 30s）内、且告警不带高风险特征（强冲击、长时间静止、姿态变化）时才关闭事件；超时或高风险时取消被拒绝并留痕，链路继续。
- **离线补传**：采集与送达相差超过阈值视为离线；事件已陈旧时跳过佩戴者询问，直接进入联系人确认。
- **单一救援链**：呼叫尝试（联系人 × 渠道）冻结为有序计划；提供商临时失败按间隔在同一尝试上重试，回执（接听/无人接/占线/失败）、确认超时、拒绝都顺位到下一响应者；全部未确认则升级急救，急救呼叫即使超过常规重试上限也继续重试，不被提供商故障阻断。
- **静默时段**：按家属时区解释、支持跨午夜；静默只跳过非紧急渠道，急救不受限。
- **位置最小开放**：仅对当前响应者短时授权（默认 10 分钟 TTL），响应者交接立即收回旧授权；每次读取、授权、收回（含拒绝）都写审计。
- **重启可续**：每次推进持久化 `pendingAction` / `nextActionAt`（JSON 原子写）。进程重启后不依赖内存定时器，调用 `pump()` 即按到期时刻继续安排下一次动作。
- **查询稳定**：时间线只追加，`entryId` 单调；旧事件晚到后查询，三个样例仍各自对应唯一救援，顺序不随重放改变。

## 运行

```bash
npm install
npm test        # tsc 类型检查 + 场景回放（断言）
npm run demo    # 仅回放，打印三段时间线
```
